# App areas (TeAmour)

One area per feedback row. Keep this list short and stable: triage counts recurrence per area, so renaming or splitting areas breaks the history. Add a new area only when `other` has collected several rows that belong together, and note the date of the change at the bottom.

> **Draft list, to be confirmed by the PM.** It reflects the product as described (team-based matchmaking, wingmen, Scout agents), not a review of the codebase.

| Area | Covers |
|---|---|
| `onboarding` | Sign-up, phone verification, first-run screens, permissions prompts. |
| `profile` | A user's own profile: photos, prompts, preferences, editing. |
| `invites` | Inviting wingmen/friends into a team, accepting invites, team membership. |
| `team` | The team space itself: who's on the team, roles (candidate vs wingman), team settings. |
| `suggest-a-match` | Wingmen suggesting prospects, the suggestion queue, approve/decline. |
| `scout` | Scout agents: interviewing wingmen, proposing prospects, the human review gate. |
| `matches` | Match cards, mutual matches, the match list. |
| `chat` | Messaging between matches and within the team. |
| `notifications` | Push and in-app notifications, their timing and wording. |
| `monetization` | Paywall, subscriptions, consumables, anything about what is free vs paid. |
| `safety-privacy` | Blocking, reporting, visibility of personal data, consent. |
| `performance` | Speed, loading, crashes not tied to a single area. |
| `other` | Anything that doesn't fit yet. Mention these in the session summary. |
